# 파지 대시보드 설계

2026-08-21

## 왜

촉각 센서가 매 프레임 힘을 재고 있는데, **실제로 쓰는 파지 경로에서는 그 값이 어디에도 안 보인다.**

| 경로 | 파지력 표시 |
|---|---|
| `roi_grasp.py` | 없음 (`force` 라는 단어조차 없다) |
| `grasp_daemon.py` → `grasp_console.py` | 없음. telemetry 페이로드에 힘이 통째로 빠져 있어 콘솔이 보여주고 싶어도 데이터가 없다 |
| `grasp_main.py` 단독 | 있음 (`_print_status`, 1초에 한 줄) |
| CSV 로그 | 있음 (사후에만) |

그 결과 "촉각이 뭘 하는지 모르겠다"가 계속됐다. 08-18/19 로그 감사에서 나온 사실들(포화 62%, 엄지 접촉률 0%, 손가락별 힘이 4배까지 갈림)은 전부 사후 분석으로만 알 수 있었고, 파지하는 동안에는 아무도 볼 수 없었다.

또 조작이 전부 키보드다(`n f t h [ ] - = , . w W r space m a q`). 무엇을 누를 수 있는지 화면에 힌트 한 줄로만 있다.

## 무엇을

`grasp_console.py` 창을 넓혀 오른쪽에 촉각 패널, 아래에 버튼바를 붙인다.

### 안 넣는 것

- **`ratio` 숫자** — ROI 오버레이 색이 이미 상태를 보여준다. 다만 **유효픽셀 경고는 남긴다**: ROI 가 통째로 무효일 때 "물체 없음"과 "센서가 못 봄"을 화면에서 갈라야 한다(카메라가 Min-Z 안으로 들어오면 조용히 깨지는 자리다).
- **`k_hand` / `object_class`** — `K_THRESHOLD=50.0` 이 아직 잠정값이라(로그 25개 런의 유일한 틈에서 유도, 위쪽 표본 2개) 화면에 띄우면 검증 안 된 숫자를 사실처럼 보이게 한다. 로그의 `class` 열에는 계속 남으므로 검증에는 지장 없다.
- **새 진입점** — 소켓·재연결·워치독 코드가 복제되고 그게 갈라진다.
- **`roi_grasp.py` 변경** — 기준선이다. 데몬/콘솔 쌍의 동작을 비교할 잣대로 남긴다.

## 계약 변경

telemetry 한 곳뿐이다.

```python
"forces": {finger_name: float | None},   # 없으면 {} (--simple-grasp / --no-hand)
"cfg": {..., "f_touch": F_TOUCH},        # 기존 cfg 에 한 필드
```

접촉 개수는 콘솔이 `forces` 와 `cfg.f_touch` 로 계산한다. 임계값을 데몬이 실어 보내는 것은 기존 `cfg` 의 존재 이유를 그대로 따른 것이다 — "데몬이 실제로 쓰는 값을 보내면 두 곳의 값이 어긋날 여지가 없다".

`forces` 가 `{}` 인 경우가 정상 경로에 있다(`--simple-grasp`, `--no-hand`). 패널은 그때 "센서 없음"을 그려야 하고, 0N 으로 그리면 안 된다 — "안 눌림"과 "센서 없음"이 같아 보인다.

## 구조

```
detection/dashboard/
  layout.py    창 분할 계산            순수 · 테스트
  buttons.py   버튼 정의 + 히트테스트 + 명령 생성   순수 · 테스트
  panels.py    촉각 패널 렌더링
detection/grasp_console.py   배선만
detection/grasp_daemon.py    telemetry 2 필드
```

렌더링과 순수 로직을 가르는 이유는 두 가지다. 테스트가 cv2 창 없이 돌고, 나중에 웹 UI 로 갈아끼울 때 `layout`/`buttons` 가 그대로 남는다.

### 버튼이 키와 같은 경로를 쓴다

`console_input.key_to_command()` 는 이미 cv2 도 소켓도 모르는 순수 함수로 키 → 명령 dict 를 만든다. 버튼도 **같은 명령 dict** 를 만든다. 그래서 `grasp_commands.py`(데몬 쪽 14개 명령)와 프로토콜은 안 바뀌고, 키 조작도 그대로 살아 있다.

함정: `m`(무장)과 `a`(정렬)는 **토글**이라 현재 상태를 알아야 한다. 그래서 `_KEYS` 에 없고 콘솔 루프가 텔레메트리를 보고 만든다. 버튼도 같아야 하므로 명령 생성 함수가 telemetry 를 받는다:

```python
button_command(button_id, tel) -> dict | None
```

토글을 텔레메트리로 만들 때는 `latest` 가 아니라 **화면에 그린 `tel`** 을 써야 한다. 눈에 보이는 상태와 뒤집는 대상이 어긋나면 안 된다(기존 `m` 키 주석의 규약).

## 커밋 순서

1. telemetry 확장 (데몬 + 테스트)
2. 순수 `layout` / `buttons` + 테스트
3. `panels` 렌더링
4. 콘솔 배선

## 이번에 안 하는 것

- 슬립 감지(`tf`) 표시. `--sensor-diag` 로 tf 가 살아 있는 것은 확인됐지만, 실제 파지 중 tf 를 쌓은 데이터가 아직 한 줄도 없다. 임계값을 정할 근거가 생긴 뒤에 붙인다.
- 파지 성공/실패 판정(`"failed"` 규약). 별개 작업이다.
- 웹 UI. `layout`/`buttons` 가 순수하게 남아 있으므로 필요해지면 그때 갈아끼운다.
