# 파이 데몬 + PC 콘솔 실행하기

`roi_grasp.py` 하나가 하던 일을 두 프로세스로 나눴다. 파이가 판정과 구동을, PC가 화면과 키 입력을 맡는다.

- 설계: `docs/superpowers/specs/2026-08-18-pi-pc-split-design.md`
- 파이 사전 준비: `docs/pi-setup.md`

---

## 무엇이 어디서 도는가

| | 파이 (`grasp_daemon.py`) | PC (`grasp_console.py`) |
|---|---|---|
| D405 카메라 | ✅ | |
| 깊이 판정 (`band_ratio`, 주축 각도) | ✅ | |
| 상태기계 (ARMED→ALIGNING→…→HOLDING) | ✅ | |
| 손·손목·촉각 센서 | ✅ | |
| 화면, ROI 드래그, 키 입력 | | ✅ |

**깊이 배열은 네트워크로 한 바이트도 안 나간다.** 640×480 float32 는 1.2MB/프레임이다. PC 로는 컬러 JPEG 와 ROI 크기 이진 마스크(150×150 PNG ≈ 500B)만 간다.

포트 두 개를 쓴다 — **5001** 제어(양방향 JSON), **5002** 미리보기(파이→PC).

---

## 띄우기

### 파이에서 (먼저)

```bash
source ~/venv/bin/activate
cd ~/haram_code/detection
python grasp_daemon.py
```

옵션:

| 옵션 | 뜻 |
|---|---|
| `--no-hand` | 모터에 연결하지 않는다. 카메라·판정만 |
| `--no-wrist` | 손목을 안 쓴다 (정렬 없이 확인 창만) |
| `--simple-grasp` | 촉각 힘 제어 대신 고정 자세 파지. 촉각 센서가 죽었을 때 |
| `--preview-fps 15` | 미리보기 프레임률 (기본 15) |
| `--preview-scale 1.0` | 미리보기 축소 배율. WiFi 가 느리면 `0.5` |
| `--host 0.0.0.0` | 리슨 주소 (기본 전체) |

`--no-hand`/`--no-wrist` 를 줘도 **카메라는 항상 필요하다.** 손과 손목만 선택이다.

### PC에서 (그다음)

```powershell
cd C:\Users\desktop\Desktop\haram_code\detection
python grasp_console.py --host <파이IP>
```

파이 IP 를 넣는다. 기본값은 `127.0.0.1` 이라 같은 기계에서 쓸 때만 맞다.

## 처음 붙였을 때

창이 뜨고 좌상단에 이런 것들이 보인다:

```
state: ARMED
DISARMED - press 'm' to arm
drag to set ROI
```

**`DISARMED` 가 정상이다.** 데몬은 무장 해제 상태로 기동한다 — 부팅하자마자 손이 알아서 잡으면 안 되기 때문이다. `m` 을 눌러야 판정이 시작된다.

## 키

| 키 | 하는 일 |
|---|---|
| 드래그 | ROI 지정 |
| `m` | **무장 / 해제** (새로 생긴 키) |
| `a` | 자동 정렬 켜기 / 끄기 |
| `n` / `f` | 밴드 near / far 를 지금 중앙값으로 (캘리브레이션) |
| `[` `]` | near 를 5mm 씩 |
| `-` `=` | far 를 5mm 씩 |
| `t` | 지금 각도를 목표 각도로 |
| `,` `.` | 목표 각도를 1도씩 |
| `h` | 손 마스크 저장 (**물체를 치운 상태에서**) |
| `w` / `W` | 손목 수동 조그 |
| `r` | 놓기 (잡고 있을 때만) |
| `space` | 비상 폄 |
| `q` | 콘솔 종료 (데몬은 계속 산다) |

`n`/`f`/`t`/`h` 는 **값이 아니라 동작**을 보낸다. 콘솔이 받은 숫자는 이미 100ms 낡았으므로, 파이가 자기 최신 값으로 계산한다. 이 규약 덕분에 이 네 키는 분리 전과 완전히 똑같이 동작한다.

키를 눌렀는데 거절되면 이유가 PC 터미널에 뜬다 (예: `[NAK] capture_target: 각도를 못 재고 있어 목표를 정할 수 없다 (too few pixels)`).

## 브링업 순서

한 번에 다 붙이지 말고 단계를 밟는다. 각 단계에서 다음으로 넘어가기 전에 눈으로 확인한다.

### 1단계 — 카메라와 판정만

```bash
python grasp_daemon.py --no-hand
```

- 콘솔 창에 영상이 뜨는가
- 드래그해서 ROI 를 잡으면 데몬 쪽에 `[INFO] roi.json 저장` 이 뜨는가
- 손을 ROI 에 넣었다 뺐다 하면 `ratio` 숫자가 움직이는가
- `n`/`f` 로 밴드를 잡으면 초록 픽셀이 물체에만 붙는가

여기서 `valid` 가 30% 아래면 `! valid NN% - sensor cannot see` 경고가 뜬다. 카메라가 너무 가까운 것이다.

### 2단계 — 각도

- 물체를 돌리면 `angle` 숫자가 따라 도는가
- 빨간 주축선이 물체를 따라가는가 (손이 아니라)
- 손을 따라간다면 물체를 치우고 `h` 로 손 마스크를 다시 찍는다

### 3단계 — 손목 (`--no-hand` 없이, `--simple-grasp`)

```bash
python grasp_daemon.py --simple-grasp
```

- `w`/`W` 로 손목이 예상한 방향으로 도는가
- `m` 으로 무장하고 물체를 넣으면 `ALIGNING` 으로 가는가
- 손목이 목표 각도 쪽으로 도는가, 오버슈트하지 않는가

오버슈트하면 `grasp_state.py` 의 `ALIGN_GAIN` 을 낮춘다. 타임아웃이 나면 올린다.

### 4단계 — 전체

```bash
python grasp_daemon.py
```

촉각 힘 제어까지 포함이다. baseline 을 잡는 동안 **손에 아무것도 닿지 않게** 한다.

## 링크가 끊기면

WiFi 가 끊기거나 콘솔이 죽으면 데몬이 2초 안에 알아채고 이렇게 한다:

| 그때 상태 | 조치 |
|---|---|
| ARMED | 무장 해제 |
| ALIGNING / CONFIRMING | 즉시 물러나 무장 해제 |
| GRASPING | **끝까지 진행** → HOLDING (중간에 멈추면 손가락이 반쯤 닫힌 채 끼인다) |
| HOLDING | 30초 후 자동 폄 |
| RELEASING | 끝까지 |

**다시 붙어도 자동으로 무장되지 않는다.** `m` 을 다시 눌러야 한다 — 사람이 화면을 보고 있다는 확인이다.

콘솔이 살아 있는 동안 자동 폄 타이머가 돌면 화면에 `! LINK LOST - auto open in NNs` 가 뜨고, 다시 붙는 순간 취소된다.

과열 보호는 이것과 별개로 항상 돈다. 모터 온도가 한계를 넘거나 온도를 못 읽으면 데몬이 스스로 손을 편다.

## 안 될 때

| 증상 | 볼 것 |
|---|---|
| 콘솔이 `ConnectionRefused` | 데몬이 안 떠 있거나 IP/포트가 다르다. 파이에서 `ss -tlnp \| grep 500` |
| 데몬이 `[INFO] D405 연결 대기 중...` 에서 멈춤 | 카메라 미연결. `rs-enumerate-devices` 로 확인 |
| 모든 모터가 `Parsing error` | **서보 전원부터 확인.** 포트가 정상으로 보여도 전원이 없으면 이렇게 나온다 |
| 포트 permission denied | `sudo usermod -aG dialout $USER` 후 **재로그인** |
| 영상이 뚝뚝 끊긴다 | `--preview-fps 8 --preview-scale 0.5` 로 낮춘다. 판정은 안 느려진다 (30Hz 그대로) |
| ROI 박스가 드래그한 자리와 다르다 | 좌표 환산 문제다. `--preview-scale 1.0` 으로 돌려 확인 |
| 뭔가 이상한데 원인을 모르겠다 | 파이에서 `python roi_grasp.py` 를 직접 돌려 본다 (아래) |

### 기준선으로 되돌아가기

`detection/roi_grasp.py` 는 **쪼개기 전과 같은 동작을 하는 단일 프로세스 버전**으로 남겨 두었다. 파이에 모니터를 붙이면 이것만으로 돌릴 수 있다.

```bash
python roi_grasp.py
```

데몬+콘솔에서 뭔가 이상하면 이걸 돌려서 같은 증상이 나는지 본다.

- 여기서도 이상하다 → 분리 탓이 아니다 (하드웨어나 캘리브레이션)
- 여기서는 멀쩡하다 → 분리하면서 생긴 문제다

이 파일은 파이 이사와 WiFi 튜닝이 다 끝날 때까지 지우지 않는다.

## 설정 파일

`roi.json`(ROI 박스·밴드·목표각)과 `hand_mask.npy`(손 마스크)는 **파이가 소유한다.** 판정하는 쪽이 가져야 PC 와 어긋나지 않는다.

PC 는 값이 바뀔 때마다 `detection/backup/roi.json` 에 사본을 떨군다. 파이 SD카드가 날아가도 캘리브레이션을 잃지 않는다. **이 백업 파일을 읽어서 쓰지는 않는다** — 두 곳에서 읽으면 어느 쪽이 진짜인지 모르게 된다.
