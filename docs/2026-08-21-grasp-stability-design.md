# 파지 안정화 — 수동 파지 · 전단력 로깅 · 벌림 탐색

2026-08-21

## 슬립의 성격 (측정)

08-18/19 로그 30회를 재서 나온 사실:

| 관측 | 값 |
|---|---|
| HOLD 중 `a` 가 열리는가 | 아니다. 경과 21초까지 Δa 중앙값 `0.0000` |
| 수직력이 시간에 따라 주는가 | 아니다. `a` 고정 구간 68개에서 dF/dt 중앙값 0, 감소:증가 46:54 |
| 더 조일 여유가 있는가 | 안정 HOLD 손가락의 62%가 `a=A_MAX` 포화 |
| 목표힘 1.8N 도달률 | 19% |

**손가락은 같은 힘으로 누르고 있는데 물체가 그 사이로 흘러내린다.** 마찰 부족이고, 수직력은 이미 포화라 못 올린다. dF/dt 가 양방향 대칭인 것이 결정적이다 — 슬립이나 응력 완화라면 한쪽으로 쏠려야 하는데 안 그렇다. 즉 **지금 보는 채널(nf)에 그 현상이 안 찍힌다.**

그래서 두 갈래로 간다:

1. **전단력(`tf`)을 쌓는다** — 슬립은 접촉면의 전단 현상이다. 드라이버가 매 프레임 보내주는데 로그에 한 줄도 없었다. 임계값은 실측 없이 못 정한다.
2. **접촉점을 늘린다** — 힘을 못 올리면 남는 레버는 접촉 지오메트리뿐이다.

## ① 수동 파지

ROI 트리거가 걸려야만 파지가 시작되면, 파지 안쪽 로직을 고칠 때마다 카메라 조건을 맞춰야 한다.

- `GraspStateMachine.request_grasp()` — `ARMED`/`ALIGNING`/`CONFIRMING` 에서 받고 곧바로 `GRASPING`
- **무장 해제·쿨다운을 무시한다.** 둘 다 "자동으로 새 파지를 시작하지 않는다"를 위한 장치라 사람의 의도를 막을 이유가 없다 (`emergency_open` 과 같은 성질)
- **진행 중인 파지는 거절한다.** 다시 시작하면 손가락이 반쯤 닫힌 채 상태가 초기화되어 물체에 끼인다
- 프로토콜 `{"cmd":"grasp"}`, 키 `g`, **GRASP** 버튼

## ② 전단력 로깅

- `TactileHand.read_shear()` — `read_forces` 와 같은 규약(모든 손가락이 키, 없거나 STALE 이면 `None`)
- `GraspLogger` 에 `tf` 컬럼. `None` 은 빈 칸이다 — 0 으로 적으면 '전단력 없음'과 '측정 안 됨'이 같아 보인다
- baseline 을 안 뺀다. 무부하 기준을 아직 안 재봤고, 원시값으로 쌓아야 나중에 다룰 방법을 정할 수 있다
- **제어에는 안 쓴다.** 임계값을 정할 데이터가 생긴 뒤에 붙인다

## ③ 벌림 탐색 (`spread_seek.py`)

접촉이 부족하면 못 찾은 손가락을 옆으로 훑어 파지 자리를 찾는다.

**핵심: 잡고 있는 손가락은 건드리지 않는다.** `kinematics.finger_command` 를 보면 벌림은 손가락 안에서 `(m1+m2)/2` 로 완결되므로 물리적으로 손가락마다 독립이다. `s` 가 손 전체 스칼라였던 건 호출부 사정일 뿐이라, `hand_pose` 가 `{손가락: s}` 도 받게 고쳤다.

그래서 **푸는 것 없이 탐색할 수 있다** — 접촉한 손가락은 `a` 도 `s` 도 그대로라 마찰이 안 줄고, 훑는 손가락은 어차피 허공이라 물체를 긁지 않는다.

- 훑는 손가락은 **하나의 `u` 를 공유**한다. 손가락마다 따로 훑으면 조합이 폭발하고 부채 관계가 깨져 인접 손가락과 부딪히는 새 경로가 생긴다
- **양방향**으로 `0 → ±STEP → ±2·STEP …` 번갈아. 어느 쪽이 물체 쪽인지 알 방법이 없고, 한쪽을 끝까지 간 뒤 반대로 가면 손가락이 전체 폭을 쓸고 지나간다
- 점수는 `(접촉 손가락 수, 합계 힘)` 사전식. 접촉 수가 먼저다 — 힘이 큰 한 점보다 닿는 손가락이 많은 쪽이 안 미끄러진다
- **게이트는 상태(HOLD 개수), 점수는 힘.** HOLD 는 확인을 거친 자리라 노이즈에 안 흔들리고, 훑는 중에는 "방금 옮긴 자리에서 닿았나"를 빨리 알아야 한다
- 힘이 `F_ABORT` 를 넘으면 즉시 중단하고 그때까지의 최고점을 쓴다
- **파지당 한 번**만. 안 그러면 손이 영원히 좌우로 떨린다
- 끝나면 `_stable = 0`. 찾은 자리에서 실제로 물릴 시간을 줘야 한다 — `NO_CONTACT` 는 `touch_confirm_cycles` 연속으로 힘이 잡혀야 되살아난다

**한계: 엄지는 못 움직인다.** `spread_weight = 0` 이라 `s` 를 아무리 줘도 꿈쩍 안 한다. 접촉률 0%인 손가락이 하필 그거다. 엄지는 `FINGER_SPREAD_BIAS_DEG`(정적 설정, 지금 0.0) 라는 별도 축이고 이번 범위 밖이다.

## 미검증 값

- `SEEK_MIN_CONTACT = 3` — 실측 분포(0개 5회 / 1개 6회 / 2개 13회 / 3개 3회 / 4개 3회)의 중앙값이 2다. 2로 두면 절반이 그냥 통과하고 4로 두면 거의 매번 훑는다. 3은 그 사이다
- `spread_seek.MAX_S = 0.3` (≈9°), `STEP = 0.1` (≈3°), `SETTLE_CYCLES = 3`
- `SEEK_ENABLED` 스위치를 남겼다. 실물에서 손가락이 물체를 밀어내면 여기서 끈다

## 이번에 안 한 것

- **`tf` 기반 슬립 감지.** 데이터부터 쌓는다
- **파지 성공/실패 판정**(`"failed"` 규약). `NO_CONTACT` 가 아직 `settled` 에 묶여 있다
- **엄지 바이어스 탐색.** 정적 설정이라 성격이 다르다
